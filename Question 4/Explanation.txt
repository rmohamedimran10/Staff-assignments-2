⁠tail -f⁠ (Real-time Display): The ⁠-f⁠ (follow) flag ensures the command doesn't just read the end of the log file and stop; it stays open, displaying newly added log entries in real-time as the server generates them.
 Pipes (⁠|⁠): The pipe acts as a bridge, taking the live output from the ⁠tail⁠ command and feeding it directly into the next command (⁠grep⁠) rather than just printing it all to the screen.
 ⁠grep⁠ (Extracting Messages): This filters the incoming stream of data, allowing only lines containing the specific string "ERROR" to pass through, effectively isolating the critical issues.
 Redirection & ⁠/dev/null⁠ (Suppressing Output): Adding ⁠2>/dev/null⁠ immediately after the ⁠tail⁠ command redirects any standard errors (like permission denied warnings) into the system's "black hole" (⁠/dev/null⁠), ensuring extraneous (irrelevant or unrelated to the subject being dealt with) system warnings don't clutter the actual error monitoring.
 ⁠tee -a⁠ (Maintaining a separate report): Because standard output redirection (⁠>>⁠) hides the output from the screen, I used ⁠tee -a⁠. This command splits the output, simultaneously displaying the ERROR lines on the terminal screen in real-time and appending (⁠-a⁠) them to ⁠error_report.txt⁠.
